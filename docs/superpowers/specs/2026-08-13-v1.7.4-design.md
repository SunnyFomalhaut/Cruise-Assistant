# v1.7.4 设计规格（全船地点目录：assets 数据文件 / 通用营业时段 / 类别扩展）

## Overview
v1.7.4 将地点目录升级为全船设施：50-100 条场所数据（公共设施/泳池娱乐/商店/青少年活动/餐饮五类）从 Kotlin 代码迁到 assets JSON 数据文件，营业时间模型从三时段演进出通用时段列表（支持多时段、跨午夜、餐次标签），事件弹窗地点下拉按类别扩展，营业时间校验覆盖所有类别。版本 1.7.4（versionCode 12）。

## 1. 数据模型演进（domain/LocationCatalog.kt）

### 1a. 通用时段
```kotlin
/** 营业时段：end < start 表示跨午夜（次日）；meal 为餐次标签，设施为 null */
data class OperatingSlot(
    val start: LocalTime,
    val end: LocalTime,
    val meal: MealPeriod? = null,
    /** 夜宵打标（导入时按规则自动判定） */
    val lateNight: Boolean = false,
)

data class OperatingHours(val slots: List<OperatingSlot> = emptyList()) {
    /** 是否配置过营业时间（空列表 = 未配置，不参与筛选/校验） */
    val isConfigured: Boolean get() = slots.isNotEmpty()
}
```
（v1.7.3 的 `OperatingHours(breakfast/lunch/dinner)` 三字段模型被取代——slots 列表 + 每时段 meal 标签。）

### 1b. 判定函数（替换 v1.7.3 版本）
```kotlin
/** 某时刻是否在任一营业时段内；跨午夜时段（end < start）：time >= start || time < end；未配置恒营业 */
fun LocationCatalogEntry.isOpenAt(time: LocalTime): Boolean {
    val h = hours ?: return true
    if (!h.isConfigured) return true
    return h.slots.any { slot ->
        if (slot.end > slot.start) {
            !time.isBefore(slot.start) && time.isBefore(slot.end)
        } else {
            !time.isBefore(slot.start) || time.isBefore(slot.end)
        }
    }
}

/** 餐次是否营业：按时段标签匹配；LATE_NIGHT 看任一 lateNight；未配置恒营业 */
fun LocationCatalogEntry.isOpenFor(period: MealPeriod): Boolean {
    val h = hours ?: return true
    if (!h.isConfigured) return true
    return h.slots.any { slot ->
        when (period) {
            MealPeriod.BREAKFAST -> slot.meal == MealPeriod.BREAKFAST
            MealPeriod.LUNCH -> slot.meal == MealPeriod.LUNCH
            MealPeriod.DINNER -> slot.meal == MealPeriod.DINNER
            MealPeriod.LATE_NIGHT -> slot.lateNight
            MealPeriod.SNACK -> slot.meal == MealPeriod.SNACK
            MealPeriod.DRINK -> slot.meal == MealPeriod.DRINK
        }
    }
}
```

### 1c. 地点条目
```kotlin
data class LocationCatalogEntry(
    val deck: Int?,          // null = 无甲板（如 Room Service "Dial 0"）
    val zone: ShipZone?,     // null = 无区域
    val placeName: String,   // 显示名（有中文用中文，否则英文）

    val hours: OperatingHours? = null,
)
```

## 2. assets 数据文件与加载

### 2a. 文件：`app/src/main/assets/locations.json`
```json
{
  "venues": [
    {
      "name": "动画师餐厅 Animator's Table",
      "deck": 9, "zone": "stern",
      "category": "meal", "group": "main",
      "slots": [
        {"start": "08:30", "end": "10:00", "meal": "breakfast"},
        {"start": "12:00", "end": "13:30", "meal": "lunch"},
        {"start": "17:45", "end": "19:45", "meal": "dinner"},
        {"start": "20:15", "end": "22:15", "meal": "dinner"}
      ]
    }
  ]
}
```
- name 为显示名；deck 数字或 null（跨层 "Deck 10 & 11" 取首层并备注）；zone bow/mid/stern
- meal 值：breakfast/lunch/dinner/snack/drink（来自数据表）；设施（general/pools/retail/youth）slots 的 meal 为 null（可省略）
- lateNight 不写入 JSON——导入时按规则自动打标

### 2b. 加载机制
- `LocationCatalog` 从静态目录改为 **object + 解析器**：`object LocationCatalog { @Volatile var loaded: Map<String, List<LocationCatalogEntry>>? = null; fun load(context): ... }`，`CruiseApp.onCreate` 调用 `load` 解析 assets JSON（org.json，Android 内置）
- 现有引用点（EventSheetViewModel 的 `BUILT_IN_LOCATION_CATALOG`、`locationPresetOptions`、校验匹配、`resolvePresetMode`、LocationPicker）改为读 `LocationCatalog.venuesByCategory()`（形态保持 Map<iconKey, List<Entry>>）
- 解析失败兜底：空目录（不崩溃，功能退化为无预置下拉）
- 单元测试：解析纯函数（JSON 字符串 → 列表）可测；assets 文件本身由构建后测试验证（可选）

## 3. 事件类别扩展

| 新类别 | iconKey | 颜色 | 数据表 |
|---|---|---|---|
| 泳池娱乐 | pool | 青 0xFF45C4B8 | POOLS |
| 商店 | shop | 橙 0xFFF2994A | RETAIL |
| 青少年活动 | youth | 紫 0xFFA97BF0 | YOUTH |
| （公共设施 → 琐事 chore，不新增） | — | — | GENERAL |

- `BUILT_IN_CATEGORIES` 追加 3 项（isBuiltIn=true）；`CategoryIcons.iconFor` 加 pool/shop/youth 图标映射（用 material icons：Pool/AutoAwesome/ChildCare 之类，选可用项）；strings 加 3 个类别名
- 数据导入映射：general→chore、pools→pool、retail→shop、youth→youth、餐饮五表→meal（group 按表：正餐餐厅表→main、酒吧表→bar、收费餐厅表→paid、快餐厅/小吃吧表→quick；早餐/午餐/晚餐表按"场所主分组"归类——动画师/魔法盛夏/航海家/皮克斯市场→main，好莱坞→main，怪兽亚洲/帕洛→paid）
- 已有航次/用户数据不受影响（类别是新建的）

## 4. UI（事件弹窗）

### 4a. 地点下拉按类别
- `locationPresetOptions(iconKey, mealPeriod)` 改为通用：meal → 4 组分组 + 餐次筛选（不变）；pool/shop/youth/chore → 对应设施列表（无分组，直接列出）+ 底部"自定义地点…"
- `resolvePresetMode` 的"类别是否有目录"判断改为 `venuesByCategory().containsKey(iconKey)`（原 BUILT_IN_LOCATION_CATALOG.keys 同理）
- 名称显示：`placeName` 直接显示（导入时已定中文/英文）

### 4b. 餐次行
- 仅 meal 类别显示（不变）

### 4c. 营业时间校验扩展到所有类别
- save() 校验条件从 `categoryIconKey == "meal"` 改为"事件类别对应的目录类别中存在匹配地点（deck/zone/placeName）且 hours 已配置"
- 文案："该设施 {时间} 不营业，营业时间：{时段列表}"（设施类）；餐饮仍"该餐厅…"——统一为"该地点 {时间} 不营业，营业时间：{...}"（简化，改一处文案）
- 未配置时段的地点（slots 空）不校验

## 5. 数据导入（用户 CSV → JSON + XLSX）

- 一次性 Python 脚本：解析用户 9 类 CSV（含 AM/PM、& 两档、跨午夜、24hrs、"Deck 10 & 11"、"Dial 0"），生成 `locations.json` + 重建 `内置地点目录.xlsx`（9 类表：GENERAL/POOLS/RETAIL/YOUTH/BREAKFAST/LUNCH/DINNER/LOUNGES/EXTRAS，列：名称|甲板|区域|营业时段|餐次标签）
- 导入规则：
  - `5:45 PM & 8:15 PM` → 两个时段，每档推断 2 小时（17:45-19:45、20:15-22:15；注释"推断值"）
  - `12:00 AM – 11:59 PM` / `Available 24hrs` → 全天（00:00-23:59）
  - 跨午夜 `9:00 AM – 1:00 AM` → (09:00, 01:00) end<start
  - 夜宵打标：餐饮类时段 且（end ≥ 22:00 或跨午夜）且 start ≥ 17:00 → lateNight=true
  - 餐次标签：BREAKFAST 表→breakfast、LUNCH→lunch、DINNER→dinner、LOUNGES→drink、EXTRAS→snack、设施类→null
  - 中文名：现有 15 个场所保留中文名（合并）；其余用英文名
  - 位置：zone 映射 Forward→bow、Midship→mid、Aft→stern；deck "10 & 11" 取 10；"Dial 0" → deck null、zone null
