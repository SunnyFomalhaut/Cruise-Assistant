# v1.7.3 设计规格（餐厅营业时间 / 餐次二级选项 / 时间校验 / 晚餐 20:15）

## Overview
v1.7.3 四项改动：(1) 餐厅数据模型与 XLSX 增加早/中/晚三个营业时段（可标记不营业）；(2) 晚餐时段选项从 20:00 改为 20:15（迪士尼探险号实际为 17:45/20:15 两档）；(3) 选择餐食时增加餐次二级选项（早餐/午餐/晚餐/夜宵/零食/酒水），按营业状态筛选地点下拉；(4) 用户自定义时间选预置餐厅时校验营业时间，不匹配则提示（可继续保存）。版本 1.7.3（versionCode 11）。

## 1. 数据模型（domain/LocationCatalog.kt）

```kotlin
/** 一个营业时段（半开区间 [start, end)） */
data class OperatingSlot(val start: LocalTime, val end: LocalTime)

/** 餐厅三时段营业时间；某时段为 null 表示该时段不营业 */
data class OperatingHours(
    val breakfast: OperatingSlot? = null,
    val lunch: OperatingSlot? = null,
    val dinner: OperatingSlot? = null,
) {
    /** 是否配置过营业时间（三时段全 null = 未配置，不参与筛选/校验） */
    val isConfigured: Boolean get() = breakfast != null || lunch != null || dinner != null
}

/** 餐次（二级选项） */
enum class MealPeriod(val label: String) {
    BREAKFAST("早餐"), LUNCH("午餐"), DINNER("晚餐"),
    LATE_NIGHT("夜宵"), SNACK("零食"), DRINK("酒水"),
}
```

`LocationCatalogEntry` 增加 `val hours: OperatingHours? = null`（null 或未配置 = 宽松处理；舞台条目不加营业时间）。

### 餐次筛选规则（纯函数，可测试）
```kotlin
/** 餐厅在某个餐次是否营业；未配置营业时间的餐厅恒视为营业 */
fun LocationCatalogEntry.isOpenFor(period: MealPeriod): Boolean {
    val h = hours ?: return true
    if (!h.isConfigured) return true
    return when (period) {
        MealPeriod.BREAKFAST -> h.breakfast != null
        MealPeriod.LUNCH -> h.lunch != null
        MealPeriod.DINNER -> h.dinner != null
        MealPeriod.LATE_NIGHT -> (h.dinner?.end?.hour ?: 0) >= 22
        MealPeriod.SNACK -> true          // 任一餐次营业即算（isConfigured 已保证至少一个）
        MealPeriod.DRINK -> h.dinner != null
    }
}
```

### 时间校验（纯函数，可测试）
```kotlin
/** 某时刻是否在餐厅任一营业时段内（半开区间）；未配置营业时间的餐厅恒视为营业 */
fun LocationCatalogEntry.isOpenAt(time: LocalTime): Boolean {
    val h = hours ?: return true
    if (!h.isConfigured) return true
    return listOfNotNull(h.breakfast, h.lunch, h.dinner)
        .any { !time.isBefore(it.start) && time.isBefore(it.end) }
}
```

### 目录初始数据
- 动画师餐厅（用户提供示例）：早餐 08:30-10:00、午餐 12:00-13:30、晚餐 18:00-22:00
- 其余餐厅：`hours = null`（未配置，宽松）——用户收集数据后批量补充
- 舞台条目：不加营业时间

## 2. 晚餐时段 20:00 → 20:15

- `strings.xml`：`dinner_time_late` "20:00" → "20:15"；`dinner_time_2000` → `dinner_time_2015` "20:15"
- OnboardingScreen / SettingsScreen 的 FilterChip 值：`LocalTime.of(20, 0)` → `LocalTime.of(20, 15)`（两处）
- `pickDinnerLinkedTime` 的 19:00 分界不变（20:15 晚餐 → 18:00 场，规则成立）

## 3. 餐次二级选项（EventSheet）

- 当 `categoryIconKey == "meal"` 且内置船、处于预置下拉模式时：地点区域上方显示一行餐次 FilterChip（6 项 + 可选"全部"）
- 状态：`EventSheetState.selectedMealPeriod: MealPeriod? = null`（null = 全部，不筛选，保持现状行为）
- 筛选：`locationPresetOptions` 过滤时应用 `entry.isOpenFor(period)`（仅 meal 目录；非 meal 类别不显示餐次行）
- 已选中项被筛掉：下拉列表不显示该餐厅，但已选值不变；用户可切回"全部"或重选

## 4. 时间校验（EventSheet 保存）

- 校验时机：save() 时，若事件地点匹配预置餐厅（deck/zone/placeName 与 meal 目录某项一致）且该餐厅 `hours.isConfigured`，检查 `startTime` 是否 `isOpenAt`；不在 → 弹 AlertDialog 提示：
  "该餐厅 {HH:MM} 不营业，营业时间：{早餐 08:30-10:00 / 午餐 12:00-13:30 / 晚餐 18:00-22:00}"
- 交互：确认"仍要保存"→ 继续；"返回修改"→ 关闭弹窗留在表单
- 实现：仿现有 pendingScopeChoice 模式（EventSheet 内 AlertDialog），save() 先做校验、命中则置标志等用户决策
- 舞台/自定义地点/未配置营业时间的餐厅不校验

## 5. XLSX 更新

五个工作表中，餐饮四表（正餐/酒吧/收费/快餐）各增加三列：**早餐**、**午餐**、**晚餐**（位于英文名之后）。单元格填 `"HH:MM-HH:MM"` 或 `"不营业"`。动画师餐厅按示例填上，其余留空（待用户收集）。舞台表不加列。表头行批注说明格式。
